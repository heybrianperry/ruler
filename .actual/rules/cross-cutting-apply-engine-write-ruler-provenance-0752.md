# Provenance Sidecar Files Track Generated Artifacts Across Apply and Revert Cycles: Apply Engine Write Ruler Provenance Json

These rules are ALWAYS ACTIVE for all apply-engine code that generates artifacts such as MCP configs, skills, subagent definitions, and settings files, as well as for revert-engine code that determines artifact ownership during cleanup cycles.

### Rules

- **R-PROV-001** MUST: The apply engine MUST write the .ruler-provenance.json sidecar atomically with its corresponding artifact so that no generated artifact exists on disk without a co-located provenance record.
- **R-PROV-002** MUST: The sidecar path MUST be generated by getGeneratedProvenancePath(artifactPath), which appends .ruler-provenance.json to the artifact's base name (e.g., mcp-config.json → mcp-config.json.ruler-provenance.json) or places it as a sibling with a deterministic naming convention.
- **R-PROV-003** MUST: The minimum required fields in the .ruler-provenance.json sidecar are: generatingCommit (SHA string), generatedAt (ISO 8601 timestamp), artifactType (string enum identifying the artifact category, e.g., 'mcp-config', 'skill', 'subagent'), and schemaVersion (integer, starting at 1).
- **R-PROV-004** MUST: trackMcpGeneratedArtifacts() and equivalent apply-engine routines MUST call getGeneratedProvenancePath() and write the sidecar immediately after successful artifact write, within the same error boundary.
- **R-PROV-005** MUST: isRulerGeneratedFile() MUST return false (not throw) when the sidecar file is absent or unparseable, and MUST log a structured warning at the diagnostic level so MCP tooling can surface provenance gaps.
- **R-PROV-006** MUST: Apply engine sidecar writes MUST include explicit error handling that rolls back or flags the artifact if the sidecar write fails, ensuring non-atomic writes do not leave artifacts without provenance.
- **R-PROV-007** MUST: The revert engine MUST handle unknown schemaVersion values in sidecar files gracefully (e.g., treat as ruler-generated with a warning) rather than throwing a parse error.
- **R-PROV-008** SHOULD: The sidecar SHOULD include a content hash or commit SHA that the revert engine can cross-reference against known apply cycles to prevent user-created .ruler-provenance.json files from being misclassified as ruler-generated artifacts.
- **R-PROV-009** SHOULD: Revert engine SHOULD log a warning and require explicit confirmation before deleting any file whose provenance sidecar references an unrecognized commit.
- **R-PROV-010** SHOULD: .ruler-provenance.json SHOULD be added to default .gitignore and .npmignore templates to prevent sidecar files from being committed to version control or included in build outputs.

### Verify

```bash
# Verify that all generated artifacts have co-located provenance sidecars
grep -r "trackMcpGeneratedArtifacts\|trackSkillGeneratedArtifacts\|trackSubagentGeneratedArtifacts" src/core/apply-engine.ts | wc -l

# Verify that getGeneratedProvenancePath is called in artifact write paths
grep -A 5 "trackMcpGeneratedArtifacts" src/core/apply-engine.ts | grep -c "getGeneratedProvenancePath"

# Verify that sidecar schema includes required fields
grep -E "generatingCommit|generatedAt|artifactType|schemaVersion" src/core/FileSystemUtils.ts | wc -l

# Verify that isRulerGeneratedFile handles missing sidecars gracefully
grep -A 10 "isRulerGeneratedFile" src/core/FileSystemUtils.ts | grep -c "return false"

# Verify integration test coverage for sidecar survival and revert behavior
grep -E "sidecar.*revert|revert.*sidecar|schemaVersion.*unknown" tests/integration/generated-sidecar-provenance.test.ts | wc -l

# Verify that error handling wraps sidecar writes
grep -B 3 -A 3 "getGeneratedProvenancePath" src/core/apply-engine.ts | grep -c "try\|catch\|error"
```

**Accept when:**
- All apply-engine artifact generation routines call getGeneratedProvenancePath() and write sidecars atomically with artifacts
- Sidecar JSON includes generatingCommit, generatedAt, artifactType, and schemaVersion fields
- isRulerGeneratedFile() returns false gracefully when sidecars are absent or unparseable, with diagnostic logging
- Apply engine error handling prevents non-atomic writes (artifact without sidecar)
- Revert engine handles unknown schemaVersion values without throwing parse errors
- Integration tests verify sidecar survival across full revert cycles and revert behavior when sidecars are absent
- .ruler-provenance.json is documented in .gitignore and .npmignore templates
