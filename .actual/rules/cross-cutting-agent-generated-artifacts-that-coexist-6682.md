# Provenance Sidecar Files Track Generated Artifacts Across Apply and Revert Cycles: Agent Generated Artifacts That Coexist User

These rules are ALWAYS ACTIVE for all agent-generated artifacts that may coexist with user-created equivalents, including MCP configs, skills, subagent definitions, and settings files.

### Rules

- **R-PROV-001** MUST: All agent-generated artifacts that may coexist with user-created equivalents MUST be stamped with a `.ruler-provenance.json` sidecar file recording at minimum the generating commit SHA and an ISO 8601 timestamp at the time of generation.
- **R-PROV-002** MUST: The sidecar file path MUST be generated by `getGeneratedProvenancePath(artifactPath)` in FileSystemUtils.ts, appending `.ruler-provenance.json` to the artifact's base name or placing it as a sibling with a deterministic naming convention.
- **R-PROV-003** MUST: The minimum required fields in the `.ruler-provenance.json` sidecar are: `generatingCommit` (SHA string), `generatedAt` (ISO 8601 timestamp), `artifactType` (string enum identifying the artifact category), and `schemaVersion` (integer, starting at 1).
- **R-PROV-004** MUST: Sidecar writes MUST be atomic with artifact writes, occurring within the same error boundary; if sidecar write fails, the artifact write MUST be rolled back or flagged.
- **R-PROV-005** MUST: `isRulerGeneratedFile()` MUST return false (not throw) when the sidecar file is absent or unparseable, and MUST log a structured warning at the diagnostic level.
- **R-PROV-006** MUST: The revert engine MUST read provenance sidecars to distinguish ruler-generated artifacts from user files during cleanup, eliminating reliance on the centralized `.ruler-managed.json` manifest for ownership decisions.
- **R-PROV-007** SHOULD: The sidecar SHOULD include a content hash or commit SHA that the revert engine can cross-reference against known apply cycles to prevent user-created sidecars from being misclassified as ruler-generated.
- **R-PROV-008** SHOULD: The revert engine SHOULD log a warning and require explicit confirmation before deleting any file whose provenance sidecar references an unrecognized commit.
- **R-PROV-009** SHOULD: `.ruler-provenance.json` SHOULD be added to default `.gitignore` and `.npmignore` templates to prevent sidecar files from being committed to version control.
- **R-PROV-010** MAY: A per-directory `.ruler-provenance-manifest.json` approach may be evaluated if per-artifact sidecars produce unacceptable file system overhead in directories with large numbers of generated artifacts.

### Verify

```bash
# Verify that all generated artifacts in known ruler output paths have corresponding .ruler-provenance.json sidecars
find .actual/mcp-configs .actual/skills .actual/subagents -type f ! -name '*.ruler-provenance.json' -exec test -f {}.ruler-provenance.json \; -print

# Verify that sidecar files contain required fields: generatingCommit, generatedAt, artifactType, schemaVersion
find .actual -name '*.ruler-provenance.json' -exec jq 'has("generatingCommit") and has("generatedAt") and has("artifactType") and has("schemaVersion")' {} \;

# Verify that generatedAt is valid ISO 8601 format
find .actual -name '*.ruler-provenance.json' -exec jq '.generatedAt | test("^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}")' {} \;

# Verify that schemaVersion is an integer >= 1
find .actual -name '*.ruler-provenance.json' -exec jq '.schemaVersion | type == "number" and . >= 1' {} \;

# Verify that revert engine correctly identifies ruler-generated files via isRulerGeneratedFile()
grep -r 'isRulerGeneratedFile' src/core/revert-engine.ts | head -5

# Verify that apply engine writes sidecars immediately after artifact writes
grep -A 5 'trackMcpGeneratedArtifacts\|trackSkillGeneratedArtifacts\|trackSubagentGeneratedArtifacts' src/core/apply-engine.ts | grep -E 'getGeneratedProvenancePath|writeFileSync'

# Verify integration test coverage for sidecar survival across revert cycles
grep -E 'sidecar.*survive|survive.*revert|generated-sidecar-provenance' tests/integration/generated-sidecar-provenance.test.ts
```

**Accept when:**
- All generated artifacts in collision-risk categories (MCP configs, skills, subagents, settings) have corresponding `.ruler-provenance.json` sidecars.
- Every sidecar contains the four required fields: `generatingCommit`, `generatedAt`, `artifactType`, and `schemaVersion`.
- The `generatedAt` timestamp is valid ISO 8601 format.
- The `schemaVersion` is an integer >= 1.
- The apply engine writes sidecars atomically with artifact writes, with explicit error handling for partial failures.
- The revert engine uses `isRulerGeneratedFile()` to distinguish ruler-generated files from user files without consulting the centralized manifest.
- Integration tests confirm that provenance sidecars survive full revert cycles.
- MCP diagnostics surface provenance-based warnings when sidecars are absent or unparseable.
- `.ruler-provenance.json` is included in `.gitignore` and `.npmignore` templates.

Claude Code MUST NOT skip or defer verification. All generated artifacts matching the scope MUST have provenance sidecars before apply cycles complete. Revert operations MUST validate provenance sidecars before deleting any file.
